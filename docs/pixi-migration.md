# Перенос боевых эффектов с Canvas 2D на PixiJS

Ветка `feature/pixi-effects`. Цель — убрать лаги заклинаний и сделать эффекты данными, которые потом
переносятся в Unity (ParticleSystem) почти без переписывания.

## Как сейчас

- `CanvasLayer.vue` — два `<canvas>` (под юнитами и над ними) вокруг DOM-слоя с юнитами (`character-component`),
  у каждого слоя свой `GlobalParticleService` (`services/particleService/ParticleSystem.ts`).
- Сервис ведёт жизнь эмиттеров (`EmitterConfig`): добавление, следование за юнитом (`follow`), полёт
  (`startX → endX`), появление и затухание (`fade*`). Это от движка не зависит — **оставляем**.
- Рисуют стратегии (`EffectStrategy.update/draw(ctx)`) — 28 типов, ~3 200 строк процедурной отрисовки
  (`canvas-effects.ts`, `combat-effects.ts`, `spell-effects.ts`): пути, градиенты, `shadowBlur` каждый кадр на CPU.
  Это и надо заменить.
- Что когда играет, описано данными в `battle/FxRegistry.ts` (`FxSpec`: тип, длительность, слой, якорь, args),
  запускает `battle/BattleFx.ts`. **Оставляем** — это уже почти формат «эффект как данные».
- Где ещё используется: `CanvasComponent` (эффекты вокруг кнопок и в модалках), `ResultParticles`,
  `PreviewStage` (коллекция), `ArenaStressView` (нагрузочный тест с профайлером по типам), `TestPageView`.

Подозреваемые источники лагов (проверить замером до переезда):
1. Канвасы в 2 раза больше слоя по каждой стороне (`offsetWidth * 2`) → в 4 раза больше пикселей на очистку и растр,
   и так у двух канвасов.
2. Процедурные штрихи со свечением (`shadowBlur`, широкие полупрозрачные штрихи) на каждом кадре.
3. Взрывы и искры — самые частые эффекты (`explosion` 33 раза, `sparkles` 21 в `FxRegistry`), каждая частица —
   отдельный `arc` + `fill`.

## Как будет

```
FxRegistry (FxSpec)  →  BattleFx  →  GlobalParticleService (жизнь эмиттеров, без изменений)
                                          │
                              ┌───────────┴────────────┐
                     PixiEffect (новое)          EffectStrategy (старое, пока не перенесли)
                     Pixi Container на слое      draw(ctx) на canvas
```

- **Рендер:** PixiJS v8 (WebGL, где можно — WebGPU). Два Pixi-канваса на месте двух нынешних (под и над юнитами),
  пока юниты остаются DOM. Разрешение — `min(devicePixelRatio, 2)` с `autoDensity`, а не жёсткое ×2.
- **Интерфейс эффекта:** `PixiEffect { create(layer, emitter, textures); update(emitter, dtMs); destroy() }`.
  Регистр типов: если у типа есть Pixi-реализация — она, иначе старая canvas-стратегия. Так переносим по одному
  эффекту, оба рендера живут вместе.
- **Частицы:** свой лёгкий эмиттер с модулями как в Unity ParticleSystem — emission (rate, bursts), start
  (lifetime, speed, size, rotation, color), over lifetime (кривые размера, цвета/альфы, скорости), gravity,
  blend mode (add/normal), shape (point, circle, cone, edge). `@pixi/particle-emitter` не берём: он под v7 и его
  формат хуже ложится на Unity. Частицы — спрайты одной текстуры в `ParticleContainer` (один draw call на эмиттер).
- **Свечение** — аддитивные спрайты мягкого круга вместо `shadowBlur`; молнии и дуги — `Graphics` с толстым
  полупрозрачным штрихом, построенным раз, а не каждый кадр. Bloom-фильтр — только если не хватит, на весь слой.
- **Текстуры:** сначала генерируем процедурно один раз при старте (мягкий круг, искра, кольцо, клуб дыма, руна,
  осколок льда) и кладём в атлас; позже художник заменит картинками — код эффектов не меняется.
- **Формат эффекта — данные:** описания эмиттеров в TS-объектах одного вида (`effects/pixi/presets/*.ts`),
  без логики. Потом сериализуются в JSON для Unity.

## Порядок работ

### Этап 0. Замер (до любых изменений)
- В `ArenaStressView` записать базу: FPS, худший кадр, мс по типам эффектов (профайлер уже есть), с разными
  включёнными слоями (ауры, статусы, вспышки), x1 и x4. Таблицу — сюда, в раздел «Замеры».
- Отдельно проверить вклад размера канваса: временно ×1 вместо ×2 — сколько даёт.

### Этап 1. Каркас Pixi
- Добавить `pixi.js@8`, грузить лениво (только в чанке арены и тестовой страницы, ~150 КБ gzip).
- `PixiLayer` (замена `CanvasLayer` с тем же API: два слоя, `provide('particleService')`, ресайз, масштаб
  интерфейса `.ui-stage`), один ticker на оба слоя, пауза, когда эмиттеров нет (как сейчас).
- В `GlobalParticleService` — второй путь отрисовки: для типов с Pixi-реализацией создаётся/обновляется/удаляется
  `PixiEffect` вместо вызова `draw(ctx)`. Перевод координат — тот же (`BattleFx.point`).
- Генератор текстур частиц и атлас.
- Свой эмиттер частиц (модули выше) + юнит-тесты на него (детерминированно с seed).
- Переключатель «Pixi / Canvas» в `ArenaStressView` для сравнения на одном бою.

### Этап 2. Самые частые и дорогие эффекты
`explosion`, `sparkles`, `flare`, `ring`, `projectile`, `impact`, `slash`, `flames` — это большая часть кадров.
После каждого — сравнение рядом со старым на тестовой странице и замер в нагрузочном тесте.

### Этап 3. Эффекты заклинаний
`lightning`, `arcs`, `screen-flash`, `light-pillar`, `ice-prison`, `frost-aura`, `drain`, `storm`, `sigil`,
`roots`, `nova`, `fire-wall`, `comet`, `stun-stars`, `ground-mark`, `aura-sphere`, `aura-burst`.

### Этап 4. Интерфейсные эффекты
`particles`, `god-rays`, `god-rays-radiance` в `CanvasComponent` (кнопки, модалки), `ResultParticles`,
`PreviewStage`. Важно: у браузера лимит живых WebGL-контекстов (~16) — в модалках не создавать Pixi на каждый
`CanvasLayer`, а держать один общий оверлей-рендер или уничтожать при закрытии.

### Этап 5. Уборка
Удалить canvas-стратегии и старый путь в сервисе, `CanvasLayer` → `PixiLayer` везде, обновить README эффектов.

### Этап 6 (позже, отдельно). Юниты в Pixi
Спрайты дворфов (атласы уже есть) в Pixi → один канвас, сортировка эффектов между юнитами по глубине,
ещё ближе к Unity. Не нужен для того, чтобы убрать лаги.

### Этап 7 (позже). Экспорт в Unity
Пресеты эмиттеров → JSON, текстуры — как есть; в Unity импортёр JSON → `ParticleSystem` (модули совпадают по
смыслу), таймлайны заклинаний (`FxRegistry`) → свой проигрыватель или Timeline.

## Правила переноса эффекта
- Внешний вид — как сейчас (сравнение рядом на тестовой странице), цвета и длительности — из `FxSpec`.
- Никакой отрисовки путей каждый кадр: геометрия строится один раз, дальше меняются transform/alpha/tint.
- Логика эффекта — в пресете (данные), код эмиттера общий.
- Удаление эффекта освобождает его объекты (`destroy({ children: true })`), текстуры общие — не удаляются.
- Тормозит — сначала профайлер, потом оптимизация.
