# CardComponent — рубашка карты

Карта с кристальной рубашкой. Рубашка разбивается за 3 клика: трещины → разломы → разлёт осколков.
После этого видно содержимое карты (слот, по умолчанию — иконка шлема).

- [CardComponent.vue](CardComponent.vue) — сама карта, наклон, раскол.
- [cardBackArt.ts](cardBackArt.ts) — генерация картинки рубашки (SVG → растровая картинка, кешируется).

## Использование

```vue
<CardComponent color="blue" />

<CardComponent
  color="yellow"
  :back="{
    variant: 'large',
    seed: 5,
    frame: { step: 38, depth: 18, spikeChance: 0.3 },
  }"
/>
```

| Проп | Тип | По умолчанию | Что делает |
|---|---|---|---|
| `color` | `'grey' \| 'green' \| 'blue' \| 'pink' \| 'red' \| 'yellow' \| 'dark' \| 'light'` | `'grey'` | Цвет редкости. Красит и лицевую сторону, и кристалл рубашки, и ядро в трещинах, и волну при раскрытии. Берётся из `--{color}-gem-color` в `App.vue`. |
| `back` | `CardBackOptions` | `{}` | Все настройки рубашки одним объектом (ниже). Всё, что не указано, берётся по умолчанию. |

## Объект `back`

```ts
interface CardBackOptions {
  variant?: 'large' | 'crystal' | 'cracked' | 'emerald'; // стиль граней
  seed?: number;                                        // рисунок граней
  frame?: Partial<FrameOptions>;                        // ледяная кромка
  image?: string;                                       // готовая картинка вместо генерации
  tint?: boolean;                                       // перекрасить картинку в цвет редкости
}
```

### `variant` — стиль граней

| Значение | Как выглядит | Кромка |
|---|---|---|
| `'large'` (по умолчанию) | Крупные грани (~40 шт.), сходятся к точке чуть выше и левее центра | есть |
| `'crystal'` | Мелкие грани (~150 шт.) в два кольца, сходятся к центру | есть |
| `'cracked'` | Карта расколота прямыми на 11 кусков, каждый кусок — объёмная «пирамидка» | есть |
| `'emerald'` | Ступенчатая огранка, как у изумруда: 4 ступени + площадка в центре | нет (край ровный, скруглённый) |

### `seed` — рисунок граней

Любое целое число. Тот же seed — всегда тот же рисунок, другой seed — другое расположение граней
при том же стиле. Если не указан, у каждого стиля свой: `large` — 21, `crystal` — 1337, `cracked` — 7, `emerald` — 1
(у `emerald` рисунок не случайный, seed почти ни на что не влияет).

От этого же seed по умолчанию зависит и рисунок кромки (см. `frame.seed`).

### `frame` — ледяная кромка

Единицы — «точки рисунка»: карта считается размером **200 × 300**. То есть `depth: 20` — это 10% ширины карты.

Кромка строится так: по периметру карты расставляются точки, от каждой строится кусок льда
между внешним (рваным) и внутренним (неровным) краем. Каждый кусок делится на светлую и тёмную половину.

| Параметр | По умолчанию | Диапазон | Что делает |
|---|---|---|---|
| `step` | `21` | 4 … 60 | **Размер кусков.** Средний шаг между точками по периметру; реальный шаг случайный, от ×0.67 до ×1.34. Меньше — много мелких зубчиков, больше — мало крупных глыб. |
| `depth` | `14.5` | 2 … 40 | **Толщина кромки** — насколько глубоко лёд заходит внутрь карты. |
| `depthJitter` | `9` | 0 … 30 | **Неровность внутреннего края.** Толщина каждого куска = `depth ± depthJitter / 2`. `0` — внутренний край ровный, как по линейке. |
| `protrudeChance` | `0.3` | 0 … 1 | **Как часто куски торчат наружу** за край карты (доля кусков). `0` — внешний край ровный, `1` — торчит всё. |
| `protrude` | `8` | 0 … 8 | **Насколько далеко торчат** наружу куски (от 3 до этого значения). Не больше 8: под это зарезервировано место вокруг картинки (`BLEED` в `cardBackArt.ts`). Остальные куски выступают максимум на 1.5. |
| `spikeChance` | `0.15` | 0 … 1 | **Как часто кристаллы врезаются внутрь** карты (на каждом отрезке кромки). `0` — без шипов. |
| `spikeLength` | `20` | 0 … 60 | **Длина шипов внутрь** (максимум; реальная — от 40% до 100% этого значения). |
| `seed` | seed граней + 2 | любое число | **Рисунок кромки.** Те же параметры, другое расположение кусков. |

Подсказки:

- Кромка «как на референсе» — крупные куски и заметная толщина: `{ step: 30–40, depth: 16–20, depthJitter: 8–12 }`.
- Аккуратная, почти ровная рамка: `{ protrudeChance: 0, spikeChance: 0, depthJitter: 2 }`.
- Если шипы `spikeLength` длиннее `depth`, они заметно вылезают на грани кристалла — это нормально, так и задумано.
- У стиля `emerald` кромки нет, `frame` на него не влияет.

### `image` и `tint` — своя картинка вместо генерации

```ts
import crystalLarge from '@/assets/card-backs/crystal-large.webp';
```
```vue
<CardComponent color="blue" :back="{ image: crystalLarge, tint: true }" />
```

| Параметр | Что делает |
|---|---|
| `image` | URL готовой картинки рубашки. Генерация пропускается, `variant` / `seed` / `frame` не используются. |
| `tint` | `true` — перекрасить картинку в цвет редкости: яркость и рисунок остаются, оттенок и насыщенность берутся от цвета. Удобно рисовать одну серую картинку на все редкости. Без `tint` картинка показывается как есть. |

Требования к картинке:

- **Холст с запасом под торчащие кристаллы** — пропорции **216 × 316**, сама карта внутри с отступом 8 со всех сторон
  (у запечённых файлов ~454 × 664 px). Проще всего — взять запечённый файл и дорисовывать поверх.
- Фон вокруг силуэта — **прозрачный**: по прозрачности картинки обрезаются блик при наклоне, а в прозрачных местах ничего не рисуется.
- Формат — **webp** или **png**. SVG тоже сработает, но сложный SVG с размытиями отрисовывается медленно (на него смотрят 42 осколка).
- Пульсация у готовой картинки — мягкое свечение из центра (граней, по которым светиться, у картинки нет).

### Запечённые рубашки

В [`src/assets/card-backs/`](../../assets/card-backs/) — 4 стиля с настройками по умолчанию в нейтральном сером
(хорошая основа и для доработки, и для `tint`):

| Файл | Что это |
|---|---|
| `crystal-large.webp` / `.svg` | `variant: 'large'` |
| `crystal-crystal.webp` / `.svg` | `variant: 'crystal'` |
| `crystal-cracked.webp` / `.svg` | `variant: 'cracked'` |
| `crystal-emerald.webp` / `.svg` | `variant: 'emerald'` |

`.svg` — редактируемый вектор (открывается в Figma / Illustrator / Inkscape, каждая грань — отдельный полигон),
`.webp` — то, что использует игра. После доработки SVG экспортируй его в webp/png того же размера.

Запечь любую другую рубашку: под каждой тестовой картой в TownView есть ссылки **«скачать: svg / webp»** —
файл скачается ровно с теми настройками и цветом, что у карты. Из кода — `downloadCardBack(color, back, fileName, 'svg' | 'webp')`
или `getCardBackSvg(color, back)` (строка SVG).

## Что ещё можно крутить в коде

Это не вынесено в проп — меняется в [cardBackArt.ts](cardBackArt.ts):

- **Количество граней стиля** — объект `VARIANTS`:
  - `large`: `radialFacets(rand, center, 3, 4, [[0.38, 0.25]])` — `3` и `4` — точек на короткой и длинной стороне. Меньше — грани крупнее.
  - `crystal`: то же, `6, 9` и два кольца.
  - `cracked`: количество кусков — `pieces.length < 11` в `crackedFacets`.
  - `emerald`: ступени — массив `steps` в `emeraldFacets`.
- **Откуда идёт свет** — `center` в `VARIANTS` (координаты на поле 200 × 300).
- **Разброс яркости граней** — `noise` в `VARIANTS`.
- **Яркость / насыщенность** — палитра в `buildCardBackSvg`: `deep` (тёмный тон), `mid` (основной, почти чистый цвет редкости), `light` (светлый).
- **Запас под торчащие кристаллы** — `BLEED` (сейчас 8). Слой осколков подстраивается сам через `ART_LAYOUT`.

## Как это работает (и почему не лагает)

- Рубашка рисуется SVG-строкой, один раз растеризуется на canvas в webp и кешируется по ключу «цвет + настройки».
  Повторные карты с теми же настройками используют готовую картинку.
- Осколков 42. Каждый — полноразмерный div с этой картинкой и `clip-path`, поэтому разлетаются куски того же рисунка.
  Анимируются только `transform` и `opacity` (считаются на GPU) — без `filter` и масок на осколках.
- Пульсация граней (маска `getCardGlowMask`) и блик при наклоне (обрезан по силуэту `getCardSilhouetteMask`) —
  только на целой карте, до первого клика.
